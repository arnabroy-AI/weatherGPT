## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/voice/transcribe upload | Untrusted audio bytes plus filename plus content type cross into provider calls |
| client → /api/voice/speak text | Untrusted text crosses into the TTS provider and returns as audio bytes |
| provider audio/text → client | Untrusted STT transcripts flow into user-facing JSON; TTS bytes stream to the client |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-05 | Denial of service | audio upload size | high | mitigate | 2MB in-memory cap checked before any provider call with HTTP 413; 30-second provider cap documented as the outer bound |
| T-09-06 | Tampering | audio content type | medium | mitigate | Explicit allowlist of ten audio media types; anything else gets HTTP 422 before provider contact |
| T-09-07 | Spoofing | STT language claims | medium | mitigate | Default language_code unknown lets the provider detect; detected code echoed to the client without trust assumptions downstream |
| T-09-08 | Information disclosure | voice provider failures | high | mitigate | Log-full server-side, send-safe sanitized 502s via the existing mapping; no audio bytes or keys in error bodies |
| T-09-09 | Denial of service | voice endpoint abuse | medium | mitigate | Same per-IP sliding-window throttle with Retry-After as the chat route on both endpoints |
| T-09-SC | Tampering | pip installs | high | mitigate | No new packages in this plan (httpx plus pytest already vendored); no install step so no legitimacy gate needed |
</threat_model>
