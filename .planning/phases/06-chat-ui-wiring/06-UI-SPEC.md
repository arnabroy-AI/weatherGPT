### Badge system (data colors — MUST match alerts-showcase exactly)

Badges are **data colors** mirroring the backend `alert_level` contract. Reuse the exact `badgeClass` strings from `frontend/components/alerts-showcase.tsx`. Never use these classes for interactive elements.

| `alert_level` | Badge text | Class (light / dark) |
|---------------|-----------|----------------------|
| Green | `Alert: Green` | `border-green-600/40 bg-green-600/10 text-green-700` / `dark:border-green-400/40 dark:bg-green-400/10 dark:text-green-300` |
| Yellow | `Alert: Yellow` | `border-yellow-600/40 bg-yellow-600/10 text-yellow-700` / `dark:border-yellow-400/40 dark:bg-yellow-400/10 dark:text-yellow-300` |
| Orange | `Alert: Orange` | `border-orange-600/40 bg-orange-600/10 text-orange-700` / `dark:border-orange-400/40 dark:bg-orange-400/10 dark:text-orange-300` |

## Chat Layout

### Route + page frame

- Route: `/chat` → `frontend/app/chat/page.tsx` (+ colocated components, e.g. `components/chat/*` or colocated in `app/chat/`).
- Frame: site `Header` (reuse — wordmark links to `/`, theme toggle, CTA re-points to `#live-demo` on landing; on `/chat` the header CTA is hidden and replaced by nothing — chat needs no CTA) → Separator → chat column (`max-w-3xl`, gutters 16/24) → footer omitted on `/chat` (app surface; footer stays on landing only).
- Chat column order (fixed): chat header row → location bar → message list (scroll region) → composer.

### Desktop (≥768px)

- Chat header row: H1 `Chat` (Heading 24px Space Grotesk) left + right-aligned controls: theme toggle + `Clear conversation` ghost button (destructive red text, 14px/600) + `Back to home` link.
- Location bar: Label 14px/600 `Location` + amber MapPin icon + input (`placeholder` per copy contract) + hint `Used for every question you send.` Input height 44px (`h-11`), `rounded-[10px]`, glass fill. Value persists across sends within the session (in-memory state); every request sends `{message, location}` with the current bar value (empty string when blank — never `null`/`undefined`).
- Message list: vertical stack, gap 16px, `min-h-[40vh]`, newest at bottom, auto-scroll to latest on send/receive with a `Scroll to latest` floating button (44px, teal) appearing when scrolled up >400px.
- Composer: single row — multiline-capable input (`textarea`, 1–4 rows auto-grow, Enter=send / Shift+Enter=newline) + Send Button (teal fill, SendHorizontal icon + `Send message` text on desktop).

### Mobile 390px (D-06 — docked input)

- Header row compresses: H1 20px + theme toggle + overflow-safe controls (Clear becomes 44px icon-only button with `aria-label="Clear conversation"`).
- Location bar stacks full-width above the message list (never beside it), input full-width 44px height.
- Messages stack single-column full-width (no side-by-side avatars); bubbles max-width 100% (user 85% right, assistant 100% left — see bubble system).
- Composer is **bottom-docked**: `sticky bottom-0` bar with glass fill + blur + top hairline border, padding 12px + `env(safe-area-inset-bottom)`; input + icon-only Send button (44px, `aria-label="Send message"`) in one row. Message list gets `padding-bottom: 16px` so the last message never hides under the dock. Zero overlap at 390×844 verified with developer tools device preset.

## Message / Bubble System

| Role | Alignment / width | Fill | Text | Extras |
|------|-------------------|------|------|--------|
| User | Right, max 85% | Solid teal-700 (`bg-teal-700 text-white`; dark `bg-teal-400 text-slate-950`) `rounded-2xl rounded-br-md` | Body 16px/400/1.5 | Timestamps use Label 14px/600 in muted slate, right-aligned under the bubble. No alert badge on user bubbles ever. |
| Assistant | Left, max 100% | `.glass-card` (glass fill + 12px blur + 16px radius) | Body 16px/400/1.5 | Alert Badge under text (when `alert_level` present); Orange/Red 2px left level-color border; `Alert: <Level>` line preserved verbatim in reply text |
| System/notice | Center, max 100% | Transparent, muted slate 14px/600 | `role="status"` text (e.g. `Location saved for this session: Pune`) | Used for location-change confirmations and history-cap notices only |

- History cap (discretion): 50 exchanges (100 message bubbles) in-memory; oldest pair drops silently past the cap with one center notice: `Older messages were trimmed to keep this session light.`
- History is in-memory React state only (D-04) — no localStorage, no persistence, cleared on reload/navigation.
- Line breaks in `reply` render as paragraphs (`whitespace-pre-wrap`); no markdown rendering in v1 (raw text, no HTML injection — render via text nodes only, never `dangerouslySetInnerHTML`).
- Loading: assistant-side skeleton bubble (glass-card with 3 shimmering bars + `Getting your answer…` status text); user bubble for the in-flight message renders immediately on send.

## Fetch Contract

- Transport: direct client `fetch` to backend (D-01, CORS already open). No Next.js proxy route.
- Endpoint: `POST {NEXT_PUBLIC_WEATHERGPT_API}/api/chat`, body `{message: string, location: string}`, `Content-Type: application/json`.
- Base URL: read from `process.env.NEXT_PUBLIC_WEATHERGPT_API` at runtime; missing/empty → unreachable panel on first load with `{BACKEND_URL}` shown as `not configured (NEXT_PUBLIC_WEATHERGPT_API is empty)`.
- Timeout: ~10s per request via `AbortController` (covers the 8s roadmap answer budget + margin); abort on unmount and on new send (previous in-flight request is aborted before a new one starts).
- Response: single JSON `{reply: string, alert_level: "Green"|"Yellow"|"Orange"|"Red"}` (D-02, no streaming).
- Error → state mapping:

| Condition | UI state |
|-----------|----------|
| 200 + `{reply, alert_level}` | Assistant bubble + Badge |
| 200 with missing/unknown `alert_level` | Assistant bubble, no Badge |
| 422 (validation) | Inline error Card on the failed message: `That message couldn't be sent. Try shorter wording.` + per-message Retry |
| 502/500 with safe `detail` | Inline error Card: `{detail or default error-state copy}` + per-message Retry (backend message quoted verbatim as text, never HTML) |
| Network failure / timeout / abort-timeout / dead backend | Unreachable panel (full copy contract + configured URL + Retry) if zero messages yet; otherwise inline error Card + composer stays usable |
| Missing/empty env var | Unreachable panel with `not configured` URL text, no fetch attempted |

- Retry (discretion): manual only — panel/button Retry re-sends the identical `{message, location}` once per click. No automatic retries, no exponential backoff in v1 (keeps the 8s demo budget predictable).
- While one request is in-flight, Send is disabled (`aria-disabled` + spinner icon) to prevent double-submit; location bar stays editable.

## Accessibility Contract (D-07 — full a11y)

| Requirement | Implementation |
|-------------|----------------|
| Landmarks | `main` with `aria-labelledby` on chat H1; header/nav/footer landmarks reused; message list is NOT a landmark |
| Message list | `role="log"` + `aria-live="polite"` + `aria-label="Conversation"` + `aria-atomic="false"` (append-only semantics; screen reader announces new replies) |
| Loading | Skeleton has `role="status"` + text `Getting your answer…` |
| Errors/unreachable | Error Cards and unreachable panel use `role="alert"` (announced immediately) |
| Badges | Badge text always includes level name (`Alert: Green`); `aria-label` mirrors visible text; color never the sole indicator |
| Labels | Location input has visible `label` + `htmlFor`; composer `textarea` has `aria-label="Type your weather question"`; Send has visible text (desktop) / `aria-label="Send message"` (mobile icon-only); Clear has text or `aria-label` |
| Focus flow | On send: focus stays in composer. On reply arrival: focus NOT stolen (live region announces). On empty-state starter click: focus moves to composer. On Clear: focus moves to composer with a `Conversation cleared.` status announcement. On route entry: focus moves to chat H1 (`tabIndex={-1}`). Error Retry buttons are reachable by Tab in DOM order. Skip-to-content link targets `#main-content`. |
| Keyboard | Enter sends / Shift+Enter newline in composer; Escape blurs composer; all controls operable by keyboard; focus-visible 2px teal ring everywhere (inherited) |
| Contrast | Body slate-700/300 on surfaces; teal-700 on white for links/icons; user-bubble white-on-teal-700; amber restricted to the location pin icon (never text) |
| Reduced motion | Instant scroll + static skeleton (above) |
